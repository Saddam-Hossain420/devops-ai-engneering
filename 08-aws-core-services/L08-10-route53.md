## 1. এই lesson-এ যা শিখবেন

- Hosted zone (public ও private), NS delegation, registrar।
- **Alias record:** apex-এ ALB-কে নির্দেশ করার Route 53-এর উপায়; TTL নেই।
- Routing policy: simple, weighted, latency, failover, geolocation।
- Change batch: atomic, `PENDING` → `INSYNC`।
- ACM certificate-এর DNS validation (L08-09-এর HTTPS)।
- `r53_plan.py`: বর্তমান বনাম কাঙ্ক্ষিত → শুধু প্রয়োজনীয় ও নিরাপদ পরিবর্তন।

## 2. এই ধারণা কোন সমস্যার সমাধান করে

ALB-এর নাম `lab08-alb-1234567890.ap-south-1.elb.amazonaws.com` — user-কে এটা দেওয়া যায় না, আর ALB বদলালে নামও বদলায়। `app.example.com` → ALB, এবং `example.com` (apex) → ALB-ও চাই।

L06-01-এ শিখেছেন, apex-এ CNAME রাখা যায় না। Route 53-এর alias এর সমাধান।

পরিচিত ভুল:

- Console-এ record "edit" করতে গিয়ে ভুল record মোছা।
- TTL ৮৬৪০০ রেখে migration — এক দিন ধরে অর্ধেক user পুরোনো server-এ।
- Domain-এর registrar-এ NS বদলানো হয়নি, তাই নতুন hosted zone-এর record কেউ দেখে না।
- Lab-এর জন্য বানানো hosted zone মোছা হয়নি — প্রতি মাসে চার্জ।

## 3. সহজ ভাষায় পরিচয়

| ধারণা | মানে |
|---|---|
| Hosted zone | একটি domain-এর record-এর পাত্র (L06-01-এর zone file) |
| Public zone | Internet থেকে resolve হয়; registrar-এ NS delegation লাগে |
| Private zone | শুধু সংযুক্ত VPC-র ভেতরে resolve হয় |
| Alias record | Route 53-এর বিশেষ A/AAAA: AWS resource-এর নাম → তার বর্তমান IP; apex-এ চলে |
| Routing policy | একই নামের একাধিক উত্তরের নিয়ম |
| Change batch | কয়েকটি পরিবর্তন একসাথে, সব-বা-কিছুই-না |

**CNAME বনাম alias:**

| | CNAME | Alias |
|---|---|---|
| Apex-এ | না | হ্যাঁ |
| TTL | আপনার দেওয়া | Target-এর |
| Resolver কী পায় | আরেকটি নাম (আবার lookup) | সরাসরি IP |
| Target | যেকোনো নাম | AWS resource (ALB, CloudFront, S3 website, অন্য record) |

## 4. বাস্তব জীবনের উদাহরণ (analogy)

### ফোনবুক ও "এই নম্বরে কল দিলে অমুকের কাছে যাবে"

- **Hosted zone** = আপনার প্রতিষ্ঠানের ফোনবুক।
- **NS delegation** = টেলিফোন বিভাগের খাতায় লেখা "এই প্রতিষ্ঠানের নম্বর ওদের ফোনবুক দেখুন"।
- **CNAME** = "এই নামের জন্য অমুক নাম দেখুন"।
- **Alias** = reception নিজেই সেই মুহূর্তের সঠিক নম্বর বলে দেয়।

### Analogy কোথায় মেলে না

- **ফোনবুক বদলালে সবাই নতুনটা দেখে।** DNS-এ resolver আগের উত্তর TTL পর্যন্ত মনে রাখে। বদলের পরে কেউ নতুন, কেউ পুরোনো উত্তর পায় (L06-01)। Route 53-এর `INSYNC` মানে Route 53-এর server আপডেট — পৃথিবীর cache নয়।
- **একটি নামের একটিই নম্বর।** Weighted বা latency routing-এ একই নাম ভিন্ন client-কে ভিন্ন উত্তর দেয়।
- **ফোনবুকের মালিক বদলালে বিভাগকে জানাতে হয় — একবার।** Hosted zone মুছে আবার বানালে NS server বদলে যায়। তখন registrar-এ আবার NS আপডেট করতে হয়, নইলে domain অচল।

## 5. Real-world engineering scenario — "পুরোনো IP থেকে ALB-এ"

TaskFlow `app.example.com` আগে একটি EC2-এর IP-তে ছিল, TTL ৮৬৪০০। এখন ALB-এ সরাতে হবে, আর team-এর একজন চাইলেন `example.com`-কেও CNAME দিয়ে ALB-এ পাঠাতে।

`r53_plan.py`-এর আসল output (হাতে তৈরি নমুনায়)। প্রথমে ভুল পরিকল্পনা:

```text
ERROR  example.com. CNAME: not allowed at the zone apex (RFC 1034) — use an alias A/AAAA record
ERROR  api.example.com. A: alias records have no TTL (Route 53 uses the target's)
ERROR  www.example.com.: CNAME cannot coexist with ['A'] — remove the old record first, or use --prune
exit=1
```

সঠিক পরিকল্পনা:

```text
WARN   app.example.com. A: current TTL 86400s — resolvers may serve the old value that long; lower the TTL first and wait 86400s before this change
UPSERT app.example.com.             A     alias  lab08-alb-1234567890.ap-south-1.elb.amazonaws.com.
UPSERT _acme-check.example.com.     TXT   60     "lab08-verification"
```

`www` ও `*.dev` অপরিবর্তিত, তাই তালিকায় নেই। শুধু যা বদলায়, সেটাই।

**শিক্ষা:**

1. আগের দিন TTL ৬০-এ নামান এবং পুরোনো TTL (এক দিন) অপেক্ষা করুন।
2. Alias-এ বদলান।
3. পুরোনো server আরও এক TTL চালু রাখুন।

## 7. গুরুত্বপূর্ণ terminology

| Term | বাংলা ব্যাখ্যা |
|---|---|
| Registrar | Domain-এর মালিকানা রাখে; NS সেখানে লেখা |
| Delegation set | Hosted zone-এর চারটি NS server |
| Alias target | ALB-এর `DNSName` ও `CanonicalHostedZoneId` |
| `EvaluateTargetHealth` | Target unhealthy হলে record উত্তর দেবে কিনা (failover-এ) |
| `UPSERT` | না থাকলে তৈরি, থাকলে বদল |
| `INSYNC` | পরিবর্তন Route 53-এর সব server-এ পৌঁছেছে |
| Split-horizon | একই নাম public ও private zone-এ ভিন্ন উত্তর |
| `\052` | Route 53 API-তে wildcard `*`-এর octal রূপ |

## 8. ভেতরে কীভাবে কাজ করে

### 8.1 Alias

Route 53 নিজের server-এ ALB-এর বর্তমান IP খুঁজে সরাসরি A record হিসেবে উত্তর দেয়। Client CNAME-এর মতো আরেকটি lookup করে না। ALB-এর IP বদলালেও record বদলাতে হয় না।

Alias-এ TTL দেওয়া যায় না — Route 53 target-এর TTL ব্যবহার করে। `r53_plan.py` alias-এ TTL দিলে error দেয়।

### 8.2 Change batch

`change-resource-record-sets`-এর সব পরিবর্তন একসাথে সফল হয় বা কোনোটাই না। CNAME → A বদলাতে একই batch-এ আগে DELETE, পরে CREATE/UPSERT। `r53_plan.py --prune` DELETE-গুলো আগে রাখে (test-এ যাচাই)।

তারপর অবস্থা দেখুন: `aws route53 get-change --id …` → `INSYNC`।

### 8.3 Private hosted zone

- VPC-র সাথে যুক্ত থাকে; ভেতরের instance-এর resolver (VPC-র `.2` address, L08-04-এর reserved address) উত্তর দেয়।
- VPC-তে `enableDnsSupport` ও `enableDnsHostnames` চালু থাকতে হয় (L08-04-এর script দ্বিতীয়টি চালু করে)।

### 8.4 ACM DNS validation

ACM একটি CNAME record দেয় (`_xxxx.app.example.com → _yyyy.acm-validations.aws`)। Hosted zone-এ বসালে certificate issue হয়, এবং record থাকলে স্বয়ংক্রিয়ভাবে নবায়ন হয়। মুছে ফেললে নবায়ন ব্যর্থ হয় (L06-07-এর মেয়াদের সমস্যা)।

> **Fedora-তে:** `dig` আসে `bind-utils` package-এ (Ubuntu-তে `bind9-dnsutils`/`dnsutils`)। বাকি সব একই।

### 9.2 আপনার domain-এ (চালানো হয়নি)

```bash
ZONE_ID=$(aws route53 list-hosted-zones-by-name --dns-name example.com --query 'HostedZones[0].Id' --output text)
aws route53 list-resource-record-sets --hosted-zone-id "$ZONE_ID" > current.json
aws elbv2 describe-load-balancers --names lab08-alb \
  --query 'LoadBalancers[0].[DNSName,CanonicalHostedZoneId]' --output text      # desired.json-এর alias-এ
python3 r53_plan.py current.json desired.json --zone example.com --out changes.json
aws route53 change-resource-record-sets --hosted-zone-id "$ZONE_ID" --change-batch file://changes.json \
  --query 'ChangeInfo.Id' --output text > change-id
aws route53 wait resource-record-sets-changed --id "$(cat change-id)"
python3 -c "import socket; print(socket.getaddrinfo('app.example.com', 80, proto=6)[0][4])"
curl -s http://app.example.com/health
```

- `example.com`-এর জায়গায় নিজের domain দিন।
- Domain না থাকলে: একটি private hosted zone (`internal.lab08`) বানিয়ে VPC-তে যুক্ত করুন, আর EC2-এর ভেতর থেকে resolve করে দেখুন। Lab-এর পরে zone মুছুন — সব record (NS/SOA ছাড়া) আগে মুছতে হয়।

### 9.3 লেখার সময়

- **CNAME-conflict-এর check এক দিকে ছিল।** Desired-এ CNAME থাকলে conflict ধরত, কিন্তু বর্তমান CNAME-এর ওপর A বসালে ধরত না (`desired-bad.json`-এর `www`)। এখন বর্তমান record-ও গোনে; `--prune`-এ পুরোনো record মুছে যাবে, তাই তখন বৈধ (test)।
- **Batch-এ DELETE শেষে ছিল।** CNAME → A-র মতো বদলে আগে DELETE লাগে, তাই এখন DELETE-গুলো সামনে।
- **নমুনা file-এ `\052` লিখতে গিয়ে** shell heredoc backslash খেয়ে ফেলেছিল (অবৈধ JSON)। Edit tool দিয়ে ঠিক করা হয়েছে।

## 12. সাধারণ ভুল ও troubleshooting

| Symptom | কারণ | সমাধান |
|---|---|---|
| `InvalidChangeBatch: … CNAME … conflicts` | একই নামে অন্য record | DELETE আগে, বা `--prune` |
| `RRSet of type CNAME … not permitted at apex` | Apex-এ CNAME | Alias A |
| `Tried to delete resource record set … but it was not found` | DELETE-এ মান হুবহু মেলে না | `list-resource-record-sets` থেকে নতুন করে plan |
| Record আছে, কিন্তু resolve হয় না | Registrar-এ NS ভুল | `dig NS example.com +trace` |
| বদলের পরেও পুরোনো IP | Resolver cache (TTL) | অপেক্ষা; আগে থেকে TTL কমানো |
| Private zone resolve হয় না | VPC-তে যুক্ত নয়, বা DNS attribute বন্ধ | Section 8.3 |
| Certificate `PENDING_VALIDATION` | Validation CNAME নেই বা ভুল zone-এ | ACM-এর দেওয়া record হুবহু |

## 13. Security, performance ও cost বিবেচনা

- **Security:**
  - Hosted zone-এর পরিবর্তনের অনুমতি সীমিত রাখুন (`route53:ChangeResourceRecordSets`, নির্দিষ্ট zone)।
  - Registrar-এ domain lock ও MFA।
  - Dangling record — মুছে-ফেলা resource-এ নির্দেশ করা CNAME — subdomain takeover-এর ঝুঁকি। Cleanup-এ DNS-ও।
- **Performance:**
  - TTL: কম মানে দ্রুত বদল, কিন্তু বেশি query।
  - Alias-এ client-এর lookup একটি কম।
- **Cost:**
  - Hosted zone-এর মাসিক চার্জ — lab-এর zone মুছুন।
  - Health check আলাদা চার্জযোগ্য।
  - Domain registration বার্ষিক।
