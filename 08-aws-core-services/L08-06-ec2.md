## 1. এই lesson-এ যা শিখবেন

- EC2-র অংশ: AMI, instance type, subnet, security group, instance profile, key pair (ঐচ্ছিক), user data, EBS root volume।
- Instance-এর জীবনচক্র: pending → running → stopping/stopped → terminated; কোন অবস্থায় কিসের বিল।
- **User data ও cloud-init:** প্রথম boot-এ TaskFlow install — এখানে internet বা NAT ছাড়াই।
- **IMDSv2:** কেন বাধ্যতামূলক।
- SSH ছাড়া প্রবেশ (Session Manager), আর instance-এর ভেতরে না ঢুকেই boot log (`get-console-output`)।
- `run-instances --dry-run` দিয়ে খরচ ছাড়া permission যাচাই; `ec2_audit.py` দিয়ে review।

## 2. এই ধারণা কোন সমস্যার সমাধান করে

L07-01-এ নিজের laptop-এ VM বানিয়েছেন। EC2 একই জিনিস, তবে অন্যের data center-এ, API দিয়ে, মিনিটে। সুবিধার সাথে আসে নতুন ভুল:

- Console-এ হাতে বানানো instance-এ কী install হয়েছে, কেউ জানে না — দ্বিতীয়টি আর একরকম হয় না ("pet server")।
- User data-য় database password, যা যেকোনো process IMDS থেকে পড়তে পারে।
- IMDSv1 চালু, app-এ SSRF bug: আক্রমণকারী `http://169.254.169.254/…/security-credentials/` থেকে role-এর credential নিয়ে গেল।
- "Stop" করা instance-এর ৫০০ GB disk মাসের পর মাস বিল তুলছে (L07-06)।

**সমাধান:** instance-কে **পুনরুৎপাদনযোগ্য** করা — AMI + user data + instance profile + tag, সব code-এ। তারপর review।

## 3. সহজ ভাষায় পরিচয়

| অংশ | কী | Local-এর তুলনা (L07-01) |
|---|---|---|
| AMI | Boot image (OS + ডিফল্ট setting) | VM-এর ISO/disk image |
| Instance type | vCPU, RAM, network ক্ষমতা (`t3.micro`, `m7i.large`) | VM-এর vCPU/RAM setting |
| User data | প্রথম boot-এ root হিসেবে চলা script (cloud-init) | Install-এর পরের setup script |
| Instance profile | Role (L08-03) | — |
| IMDS | `169.254.169.254` — instance নিজের তথ্য ও credential পায় | — |
| EBS root volume | Network disk (L08-07) | VM-এর virtual disk |

| অবস্থা | Compute বিল | EBS বিল | Public IPv4 বিল |
|---|---|---|---|
| running | হ্যাঁ | হ্যাঁ | হ্যাঁ |
| stopped | না | **হ্যাঁ** | Elastic IP হলে হ্যাঁ |
| terminated | না | `DeleteOnTermination=false` হলে **হ্যাঁ** | Elastic IP release না করলে হ্যাঁ |

## 4. বাস্তব জীবনের উদাহরণ (analogy)

### হোটেলের ঘর

- **AMI** = ঘরের মানক সাজানো (বিছানা, টেবিল)।
- **User data** = check-in-এর সময় দেওয়া নির্দেশ ("পানি ও ফল রাখবেন")।
- **Instance type** = ঘরের মাপ।
- **Terminate** = check-out — ঘর অন্যকে দেওয়া হয়।

### Analogy কোথায় মেলে না

- **Check-out করলে মালপত্র সাথে যায়।** Terminate করলে ঘর যায়, কিন্তু `DeleteOnTermination=false` থাকা disk "লকারে" থেকে যায় — আর ভাড়া চলতে থাকে।
- **নির্দেশ শুধু রিসেপশন জানে।** User data instance-এর **যেকোনো process** IMDS থেকে পড়তে পারে, এবং `ec2:DescribeInstanceAttribute` অনুমতিধারী যে কেউ API দিয়ে। Secret রাখার জায়গা নয়।
- **ঘরে ঢুকতে চাবি লাগে।** EC2-তে SSH key ছাড়াই Session Manager দিয়ে ঢোকা যায়, আর একেবারে না ঢুকেই boot log পড়া যায়। Port 22 খোলাই লাগে না।

## 7. গুরুত্বপূর্ণ terminology

| Term | বাংলা ব্যাখ্যা |
|---|---|
| AMI | Amazon Machine Image — boot image, region-নির্দিষ্ট id |
| cloud-init | Linux image-এর boot-সময়ের setup tool; user data চালায় |
| IMDSv2 | Session token-ভিত্তিক metadata service; `HttpTokens=required` |
| Hop limit | IMDS response কয়টি network hop যাবে — container-এ ২ লাগতে পারে |
| Burstable (T) instance | CPU credit-ভিত্তিক; নিয়মিত ভারী CPU-তে বাড়তি চার্জ বা throttle |
| Launch template | run-instances-এর setting-এর সংরক্ষিত, versioned রূপ |
| Instance store | Host-এর local disk — stop করলে মুছে যায় |
| Dry run | Permission যাচাই, resource তৈরি নয় |

## 8. ভেতরে কীভাবে কাজ করে

### 8.1 User data

- প্রথম boot-এ একবার root হিসেবে চলে। আবার চালাতে হলে cloud-init-এর নিয়ম আলাদা।
- সর্বোচ্চ ১৬ KB (base64-এর আগে)।
- `make_user_data.py` TaskFlow-কে gzip + base64 করে ঢোকায় (মোট ১০,৫০২ byte), এবং boot-এর সময় `sha256sum -c` দিয়ে যাচাই করে।
- App শুধু Python standard library-তে লেখা, তাই Ubuntu AMI-র `python3`-ই যথেষ্ট — **NAT বা internet লাগে না।** এতে Lab B-তে NAT-এর খরচ বাঁচে।

সীমা: প্রতিটি instance-এর নিজস্ব SQLite file। দুটি instance-এর data আলাদা থাকবে — lab-এর জন্য ঠিক, production-এ managed database লাগবে।

### 8.2 IMDSv2

```bash
TOKEN=$(curl -sX PUT http://169.254.169.254/latest/api/token -H "X-aws-ec2-metadata-token-ttl-seconds: 300")
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/iam/security-credentials/
```

আগে একটি `PUT` দিয়ে token নিতে হয়। সাধারণ SSRF সাধারণত শুধু GET পাঠাতে পারে, তাই credential-এ পৌঁছায় না। Hop limit ১ রাখলে container-এর ভেতর থেকে token নেওয়া যায় না — container-এর IMDS দরকার হলে ২।

### 8.3 SSH নয়

- **Session Manager:** instance profile-এ `AmazonSSMManagedInstanceCore` + SSM endpoint-এ পৌঁছানোর পথ (NAT বা VPC interface endpoint — দুটোই চার্জযোগ্য)।
- NAT-হীন lab-এ shell না থাকলেও `aws ec2 get-console-output` দিয়ে cloud-init-এর output পড়া যায়।

### 8.4 Instance type ও খরচ

- `t3`/`t4g` burstable। T3-এর ডিফল্ট "unlimited" mode-এ credit ফুরালে বাড়তি চার্জ হতে পারে — documentation দেখুন।
- `t4g` ARM (Graviton) — AMI-ও arm64 হতে হবে।
- কোনো দাম এখানে লেখা হয়নি; region ও তারিখসহ pricing page দেখুন (L07-06-এর নিয়ম)।

> **Fedora-তে:** Fedora-র নিজের cloud AMI আছে, এবং cloud-init সেখানেও কাজ করে। কিন্তু এই course-এর AMI Ubuntu। User data-র `useradd`, `systemctl` দুই distro-তেই একই; `/usr/sbin/nologin`-ও আছে।

### 9.2 Dry run ও launch (আপনার account-এ — চালানো হয়নি)

```bash
export AWS_PROFILE=learn-admin AWS_REGION=ap-south-1
AMI=resolve:ssm:/aws/service/canonical/ubuntu/server/24.04/stable/current/amd64/hvm/ebs-gp3/ami-id
RUN=(aws ec2 run-instances --image-id "$AMI" --instance-type t3.micro
     --subnet-id "$APP_A" --security-group-ids "$APP_SG" --iam-instance-profile Name=taskflow-app
     --metadata-options HttpTokens=required,HttpEndpoint=enabled,HttpPutResponseHopLimit=1
     --user-data file://user-data.sh
     --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=lab08-app-a},{Key=Project,Value=lab08},{Key=Owner,Value=YOU}]'
                          'ResourceType=volume,Tags=[{Key=Project,Value=lab08},{Key=Owner,Value=YOU}]')
"${RUN[@]}" --dry-run          # permission থাকলে: "Request would have succeeded, but DryRun flag is set." — কিছু তৈরি হয় না
"${RUN[@]}" --query 'Instances[0].InstanceId' --output text      # 💰 এখান থেকে বিল শুরু
```

- Ubuntu-র SSM parameter path Canonical প্রকাশ করে; region-এ আছে কিনা `aws ssm get-parameters --names …` দিয়ে দেখুন।
- `$APP_A` ও `$APP_SG` L08-04 ও L08-05 থেকে।

শেষ command-এ কিছু না আসা পর্যন্ত শেষ নয়।

### 9.5 লেখার সময়

- **Bash heredoc-এর ভেতরে Python লিখে file বদলানোর সময়** `"\n"` আসল newline হয়ে গিয়েছিল, ফলে `userdata_lint.py` syntax error দিল। Edit tool দিয়ে ঠিক করা হয়েছে, এবং যুক্তি সরল করা হয়েছে (লাইন ধরে regex)।
- L05-10-এর secret scanner শুধু quote-এর ভেতরের মান ধরে। Shell-এর `export DB_PASSWORD=hunter2…` ধরতে user-data lint-এ আলাদা নিয়ম যোগ হয়েছে। `$(aws ssm get-parameter …)` দিয়ে runtime-এ আনা মান flag হয় না (test-এ যাচাই)।
- `ec2_audit.py` প্রথমে role-হীন instance-এও IMDSv1-কে "role-এর credential চুরি" বলে CRITICAL দিত। এখন role থাকলে CRITICAL, না থাকলে WARN (test)।
- Test-এর প্রথম regex user-data-র payload খুঁজে পায়নি, কারণ `<<'B64'`-এর পরে একই লাইনে pipe আছে। ঠিক করা হয়েছে।

## 10. Code-এর ব্যাখ্যা

| অংশ | কী করে | কেন |
|---|---|---|
| `gzip.compress(mtime=0)` | একই input → একই output | Script diff-যোগ্য, reproducible |
| `sha256sum -c` boot-এ | Payload যাচাই | আংশিক বা নষ্ট copy চলবে না |
| `User=taskflow`, `ProtectSystem=strict` | Root নয়, read-only filesystem | L01-10-এর hardening |
| `TASKFLOW_HOST=0.0.0.0` | ALB পৌঁছাতে পারে | `127.0.0.1`-এ bind = "connection refused" (L08-05) |
| `/health` loop, `exit 1` | Boot log-এ সাফল্য/ব্যর্থতা স্পষ্ট | `set -e` + স্পষ্ট বার্তা |
| `SHELL_SECRET` | Quote-ছাড়া shell assignment | L05-10-এর ফাঁক |
| IMDSv1 + role → CRITICAL | ঝুঁকির মাত্রা প্রেক্ষাপট অনুযায়ী | Role না থাকলে চুরির কিছু নেই |

| Terminate-এর পরে volume তালিকা | খালি |
| `python3 -m unittest -v` | `Ran 6 tests`, `OK` |

## 12. সাধারণ ভুল ও troubleshooting

| Symptom | কারণ | সমাধান |
|---|---|---|
| `InvalidParameterValue: User data is limited to 16384 bytes` | বড় user data | Artifact S3-এ রেখে role দিয়ে আনুন |
| App চলে না, console-এ `sha256sum: WARNING` | Payload নষ্ট | Script আবার বানান |
| ALB-এ unhealthy, instance-এ app চলছে | `127.0.0.1`-এ bind, বা SG | `TASKFLOW_HOST=0.0.0.0`; `sg_reach.py` |
| `UnauthorizedOperation` | IAM বা PassRole | L08-03 |
| `InsufficientInstanceCapacity` | AZ-এ সেই type নেই | অন্য AZ বা type |
| Instance-এ credential নেই | Profile নেই, IMDS hop limit, বা IMDSv1-এর পুরোনো SDK | `ec2_audit.py`; SDK আপডেট |
| SSM-এ instance দেখা যায় না | Agent-এর পথ নেই (NAT/endpoint), বা policy নেই | Section 8.3 |

## 13. Security, performance ও cost বিবেচনা

- **Security:**
  - IMDSv2 required।
  - Public IP নয় (ALB-এর পেছনে)।
  - Port 22 নয়।
  - User data-য় secret নয়।
  - Role least privilege (L07-05)।
  - Account-স্তরে নতুন instance-এ IMDSv2 ডিফল্ট করার setting আছে — documentation দেখুন।
- **Performance:**
  - Burstable instance নিয়মিত ভারী CPU-তে ধীর হয় বা বাড়তি চার্জ হয়।
  - Load test (L05-13-এর baseline) দিয়ে type বাছুন।
- **Cost:**
  - Terminate, stop নয়।
  - `DeleteOnTermination=true`।
  - Tag।
  - Budget alert (L08-01) এই lesson-এর আগেই চালু থাকা উচিত।
