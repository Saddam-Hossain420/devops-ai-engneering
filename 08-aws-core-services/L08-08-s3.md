## 1. এই lesson-এ যা শিখবেন

- S3-এর মডেল: bucket (region-এ, নাম বিশ্বজুড়ে অনন্য), object (key + data + metadata), prefix।
- **কে পড়তে পারে:** IAM policy + bucket policy + Block Public Access + (পুরোনো) ACL।
- TLS-only bucket policy; VPC endpoint-সীমিত access।
- Versioning, lifecycle, storage class, Object Lock — দুর্ঘটনা ও খরচ।
- Presigned URL: login ছাড়া সাময়িক access — SigV4 নিজে হিসাব করে বোঝা।
- `s3_audit.py`: public exposure ও খরচের ঝুঁকি।

## 2. এই ধারণা কোন সমস্যার সমাধান করে

TaskFlow-এর upload (avatar, report) কোথায় থাকবে? EC2-এর disk-এ রাখলে instance বদলালে হারায়, আর দুটি instance আলাদা file দেখে (L08-07)। S3 দেয় সীমাহীন, টেকসই object storage।

কিন্তু S3 cloud-এর সবচেয়ে বেশি আলোচিত data ফাঁসের উৎস। পরিচিত ঘটনা:

- "Website-এর জন্য" bucket public করা হলো; পরে একই bucket-এ customer export রাখা হলো।
- Versioning নেই; একটি script ভুল prefix-এ `aws s3 rm --recursive` চালাল — ফেরানোর পথ নেই।
- Versioning আছে, কিন্তু lifecycle নেই; প্রতিদিনের overwrite-এ পুরোনো version জমে storage বিল কয়েকগুণ।

## 3. সহজ ভাষায় পরিচয়

| ধারণা | মানে |
|---|---|
| Bucket | Object-এর পাত্র; একটি region-এ; নাম বিশ্বজুড়ে অনন্য |
| Object key | `uploads/u/42/avatar.png` — folder নেই, শুধু `/` সহ নাম ("prefix") |
| Block Public Access (BPA) | Account ও bucket-স্তরের চারটি সুইচ — public policy/ACL আটকায় |
| Bucket policy | Bucket-এর resource policy (`Principal` থাকে) |
| Object Ownership `BucketOwnerEnforced` | ACL বন্ধ; সব object bucket-মালিকের |
| Versioning | Overwrite/delete-এর পরে আগের version থাকে |
| Lifecycle | বয়স অনুযায়ী class বদল বা মোছা |
| Presigned URL | Signature-যুক্ত সাময়িক URL |

**Access-এর সিদ্ধান্ত (L07-05-এর নিয়ম):** একই account-এর principal-এর জন্য IAM policy **বা** bucket policy-র Allow যথেষ্ট, আর যেকোনো explicit Deny জেতে। Anonymous (internet) access সম্ভব শুধু bucket policy বা ACL দিয়ে — BPA সেটাই আটকায়।

**Local-এর তুলনা:** S3 filesystem নয়। Rename নেই (copy + delete), append নেই, `ls` একটি API call যার page আছে (L08-02-এর paginator)।

## 4. বাস্তব জীবনের উদাহরণ (analogy)

### গুদামের লকার

- **Bucket** = একটি গুদাম।
- **Key** = লকারের নম্বর-লেবেল।
- **Bucket policy** = গুদামের গেটের নিয়ম।
- **BPA** = মালিকের মাস্টার-সুইচ: "যা-ই লেখা থাকুক, জনসাধারণ ঢুকবে না"।
- **Presigned URL** = নির্দিষ্ট লকারের জন্য সময়-সীমিত পাস।

### Analogy কোথায় মেলে না

- **লকার খোলা থাকলে পথচারী দেখে ফেলে — কিন্তু খুঁজে পেতে হয়।** Public bucket-এর নাম অনুমান করে স্বয়ংক্রিয় scanner পুরো তালিকা নামিয়ে নেয়। "কেউ জানে না" নিরাপত্তা নয়।
- **পাস হারালে গার্ড চিনে আটকায়।** Presigned URL মেয়াদ পর্যন্ত **যার হাতে, তার জন্যই** বৈধ। Log বা chat-এ গেলে কেউ আটকাবে না। Signer-এর credential বাতিল করলে বা মেয়াদ শেষ হলে অকেজো হয়।
- **জিনিস ফেলে দিলে ফেলে দেওয়া।** Versioning-এ "delete" শুধু একটি delete marker; আগের version থাকে এবং বিল হয়। আবার versioning ছাড়া overwrite মানে আগেরটা চিরতরে শেষ।

## 5. Real-world engineering scenario — "Website-এর bucket"

Marketing team একটি static page-এর জন্য bucket বানাল, console-এ BPA বন্ধ করে public-read policy দিল। ছয় মাস পরে কেউ সুবিধার জন্য একই bucket-এ `exports/customers.csv` রাখল।

`s3_audit.py`-এর আসল output (হাতে তৈরি নমুনায়):

```text
lab08-public-site: 6 finding(s)
  CRITICAL  policy PublicRead allows s3:GetObject to everyone
  CRITICAL  block public access off: BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets — turn all four on unless this is a deliberate public website (prefer CloudFront + OAC)
  WARN      no Deny for aws:SecureTransport=false — plain HTTP requests are allowed
  WARN      versioning never enabled — an overwrite or delete cannot be undone
  WARN      object ownership ObjectWriter — ACLs active; BucketOwnerEnforced disables them
  INFO      no AbortIncompleteMultipartUpload rule — failed uploads' parts stay billed
lab08-uploads: 1 finding(s)
  WARN      versioning on but no NoncurrentVersionExpiration — old versions accumulate (and are billed)
```

**শিক্ষা:**

- Public content-এর জন্য আলাদা bucket, এবং BPA চালু রেখে CloudFront + Origin Access Control।
- Data bucket কখনো public নয়।
- Account-স্তরে BPA চালু রাখুন, যাতে একটি ভুল bucket-setting-ও আটকায়।

## 7. গুরুত্বপূর্ণ terminology

| Term | বাংলা ব্যাখ্যা |
|---|---|
| Strong consistency | লেখার পরপরই পড়লে নতুন data (S3-এ এখন ডিফল্ট) |
| SSE-S3 / SSE-KMS | Server-side encryption — S3-এর key / KMS key (নতুন object ডিফল্টে SSE-S3) |
| Storage class | Standard, Intelligent-Tiering, Standard-IA, Glacier … — দাম ও access-এর trade-off |
| Delete marker | Versioned bucket-এ delete-এর চিহ্ন; আগের version থাকে |
| Multipart upload | বড় object খণ্ডে; অসম্পূর্ণ খণ্ডও বিল হয় |
| Object Lock | WORM — নির্দিষ্ট সময় মোছা যায় না (ransomware-প্রতিরোধী backup) |
| OAC | Origin Access Control — শুধু CloudFront bucket পড়তে পারে |
| SigV4 | AWS-এর request signing algorithm |

## 8. ভেতরে কীভাবে কাজ করে

### 8.1 ডিফল্ট setting (২০২৩ থেকে)

- নতুন bucket-এ BPA চালু ও ACL বন্ধ (`BucketOwnerEnforced`)।
- নতুন object ডিফল্টে SSE-S3-এ encrypted।

তাই আজকের ভুলগুলো সাধারণত কেউ **ইচ্ছা করে বন্ধ** করার ফল, বা পুরোনো bucket-এ। `s3_audit.py` এগুলোই খোঁজে।

### 8.2 Public কি না

একটি `Allow` + `Principal "*"` statement public হয়, যদি না condition তাকে সীমিত করে — যেমন `aws:SourceVpce`, `aws:PrincipalOrgID`, `aws:SourceIp`। Audit এই key-গুলো দেখে (test-এ VPC endpoint-সীমিত policy public নয়)।

BPA-র `RestrictPublicBuckets` চালু থাকলে public policy আজ কার্যকর নয়। তখন audit CRITICAL নয়, WARN দেয় — policy-টা তবুও মুছে ফেলা উচিত।

### 8.3 Presigned URL ও SigV4

`presign.py`-এর ধাপ:

1. **Canonical request:** method, path, sorted query, `host` header, `UNSIGNED-PAYLOAD`।
2. **String to sign:** algorithm, সময়, scope (`date/region/s3/aws4_request`), canonical-এর SHA-256।
3. **Signing key:** `HMAC("AWS4"+secret, date) → region → s3 → aws4_request`।
4. **Signature:** signing key দিয়ে string-to-sign-এর HMAC।

Secret URL-এ যায় না। কিন্তু অস্থায়ী credential-এর session token URL-এ যায়, এবং URL-এর মেয়াদ credential-এর মেয়াদ ছাড়াতে পারে না। SigV4-এ সর্বোচ্চ মেয়াদ ৭ দিন।

### 8.4 Versioning ও lifecycle একসাথে

Versioning ছাড়া একটি ভুল delete স্থায়ী। Versioning-এর সাথে lifecycle-এ `NoncurrentVersionExpiration` না থাকলে প্রতিটি overwrite storage বাড়ায়। `AbortIncompleteMultipartUpload` ব্যর্থ বড় upload-এর খণ্ড পরিষ্কার করে।

> **Fedora-তে:** কোনো পার্থক্য নেই — AWS CLI ও Python।

### 9.3 আপনার account-এ (চালানো হয়নি)

```bash
export AWS_PROFILE=learn-admin AWS_REGION=ap-south-1
B=lab08-uploads-$(aws sts get-caller-identity --query Account --output text)    # অনন্য নাম
aws s3control get-public-access-block --account-id "${B##*-}"                    # account-স্তরের BPA
aws s3api create-bucket --bucket "$B" --create-bucket-configuration LocationConstraint=$AWS_REGION
aws s3api put-bucket-tagging --bucket "$B" --tagging 'TagSet=[{Key=Project,Value=lab08}]'
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled
sed "s/BUCKET/$B/g" sample/bucket-policy-tls-only.json > /tmp/policy.json
aws s3api put-bucket-policy --bucket "$B" --policy file:///tmp/policy.json
aws s3api put-bucket-lifecycle-configuration --bucket "$B" --lifecycle-configuration file://sample/lifecycle-good.json

echo hello > /tmp/a.txt && aws s3 cp /tmp/a.txt "s3://$B/u/42/a.txt"
eval "$(aws configure export-credentials --format env)"
python3 presign.py --bucket "$B" --key u/42/a.txt --region $AWS_REGION --expires 120 --profile-env > /tmp/url
curl -s "$(cat /tmp/url)"                       # hello
sleep 130; curl -s -o /dev/null -w '%{http_code}\n' "$(cat /tmp/url)"     # 403 — মেয়াদ শেষ
```

Audit-এর জন্য header-এ দেওয়া পাঁচটি `get-*` command চালান, তারপর `s3_audit.py s3/*/` — লক্ষ্য `ok`।

**Cleanup:** versioned bucket-এ `aws s3 rm --recursive` সব version মোছে না। Version ও delete marker মুছতে হয়:

```bash
for kind in Versions DeleteMarkers; do
  aws s3api list-object-versions --bucket "$B"     --query "{Objects: $kind[].{Key:Key,VersionId:VersionId}, Quiet: \`true\`}" --output json > /tmp/del.json
  grep -q '"Objects": null' /tmp/del.json || aws s3api delete-objects --bucket "$B" --delete file:///tmp/del.json
done
aws s3api delete-bucket --bucket "$B"
```

একবারে সর্বোচ্চ ১০০০টি object মোছা যায় — বড় bucket-এ loop লাগে, বা lifecycle দিয়ে মোছান। L08-12-এর cleanup script এগুলো সামলায়।

| `IllegalLocationConstraintException` | `us-east-1`-এর বাইরে LocationConstraint নেই, বা ভুল | `--create-bucket-configuration` |
| `BucketAlreadyExists` | নাম অন্য কারও | Account id/suffix যোগ |
| `AccessDenied` on `put-bucket-policy` | BPA-র `BlockPublicPolicy` public policy আটকাচ্ছে | ঠিক আচরণ — policy public করবেন না |
| Presigned URL: `SignatureDoesNotMatch` | Region ভুল, key encoding, বা ঘড়ির পার্থক্য | Region-নির্দিষ্ট host; `date -u` |
| Presigned URL: `ExpiredToken` আগেই | অস্থায়ী credential-এর মেয়াদ শেষ | URL-এর মেয়াদ ≤ session |
| `delete-bucket`: `BucketNotEmpty` | পুরোনো version বা delete marker | Section 9.3-এর cleanup |
| বিল অপ্রত্যাশিতভাবে বেশি | পুরোনো version, অসম্পূর্ণ multipart, NAT দিয়ে S3 | Lifecycle; gateway endpoint |

## 13. Security, performance ও cost বিবেচনা

- **Security:**
  - Account-স্তরে BPA।
  - Data bucket-এ TLS-only policy ও `BucketOwnerEnforced`।
  - Role-ভিত্তিক access (L08-03)।
  - Presigned URL-এর মেয়াদ মিনিটে।
  - Backup bucket-এ versioning + Object Lock বিবেচনা।
  - Access log বা CloudTrail data event চার্জযোগ্য — প্রয়োজনমতো।
- **Performance:**
  - Prefix-প্রতি উচ্চ request হার সম্ভব।
  - বড় file-এ multipart।
  - একই region-এ EC2 থেকে gateway endpoint।
- **Cost:**
  - Storage class।
  - পুরোনো version ও multipart-এর lifecycle।
  - Internet egress (CloudFront কম হতে পারে — pricing দেখুন)।
  - NAT দিয়ে S3 নয় (L08-04)।
